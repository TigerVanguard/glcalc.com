## §0 实测基线（2026-09-27，pagespeed.web.dev，Lighthouse 13.5.0 / Moto G Power / Slow 4G）

| 页面 | 分数 | FCP | LCP | TBT | CLS |
|---|---|---|---|---|---|
| `/` | 71 | 4.1 s | 4.8 s | 0 ms | 0 |
| `/glycemic-load-calculator` | **57** | 3.2 s | 4.7 s | **830 ms** | 0.025 |
| `/a1c-to-eag-calculator` | 70 | 3.9 s | 5.1 s | 80 ms | 0 |
| `/gmi-calculator` | 71 | 4.1 s | 4.8 s | 0 ms | 0 |

PSI 诊断（原文要点）：

- **Render-blocking requests，估计可省 1,050~1,200 ms**：`fonts.googleapis.com/css2?...` 750 ms；站内 `/assets/index-*.css` 200 ms。
- **GL 页**：Reduce JavaScript execution time 1.4 s；Minimize main-thread work 2.8 s；10 个长任务。
- **全部页面**：Reduce unused JavaScript 约 106~113 KiB。

## §1 根因（已核实）

1. `index.html` 在 `<head>` 里同步加载 Google Fonts 样式表（`Fraunces:opsz,wght@9..144,600;9..144,700` + `Manrope:wght@500;700;800`，`display=swap`），以及对 `fonts.googleapis.com` / `fonts.gstatic.com` 的 preconnect。跨域样式表阻塞首屏渲染。
2. 全站只有一个 JS 入口包 `dist/assets/index-*.js`，约 515 KB。其中 `src/data/gi.json`（279 KB，4893 条）被整体打入，即使 GMI、A1C、换算等页面完全用不到它。`gi.json` 以 JS 对象字面量形式内联，解析成本高于 `JSON.parse`。
3. 引用 `gi.json`（直接或间接）的只有三个页面：`GlCalculatorPage`（经 `App.jsx`、`FoodSearch`、`glStaticTable`）、`GiLookupPage`（经 `FoodSearch`、`giData`）、`GlChartPage`（经 `glChartTable` → `glStaticTable`）。
4. **交互风险（必须一起处理）**：首页和 GMI 页的 TBT 为 0，很可能是因为首屏被字体拖到约 4 秒，JS 执行落在 FCP 之前，不计入 TBT。只修字体、不拆包，FCP 提前后这些 JS 长任务可能计入 TBT，导致其他页面分数反而下降。所以 PF-01 和 PF-02 都做完之后，才做线上验收。

## §2 仓库实况与不变量（动手前必读）

- 栈：Vite 5 + React 17 CSR + 构建后 Playwright 预渲染（`scripts/prerender.mjs`，9 个路由）。**禁止**迁框架、禁止 SSR/hydrate 改造。
- `src/index.jsx` 使用 `ReactDOM.render`（**不是** hydrate），render 会整块替换预渲染的 DOM。render 回调给 `#root` 设置 `data-render-complete="true"`，`prerender.mjs` 靠这个标记判断何时截取 DOM。
- 统一验收门：`npm run check` = unit → build(+prerender) → verify-dist → e2e。当前基线全绿：unit 85、e2e 107、verify-dist 全 PASS。
- Playwright 分两个项目：`static`（对 `dist/` 的预渲染产物，含禁 JS 断言）和 `app`（对 dev server 的交互测试）。
- `semantic-ui-react` / `semantic-ui-css` 在 `package.json` 里，但 `src/` 中没有任何引用（死依赖，本 Spec 不处理）。
- 全局样式入口是 `src/styles/app.css`（由 `src/index.jsx` 引入）。`src/index.css` 是零引用的死文件，**不要**往里写。
- 任务纪律（AGENTS.md）：开工前在 `tasks.md` 登记 `[~]`，完成后 `[x]` + 证据；同一时刻只有一个 `[~]`；单个 ticket 修复循环 5 次未过就暂停，标 `[!]` 请站长介入。执行子代理**不 commit、不改 tasks.md**（编排者负责）。

## §3 锁定决策（不得重开）

| # | 决策 | 理由 |
|---|---|---|
| D1 | 字体改为**站内托管**，保留 Fraunces + Manrope，视觉零变化：照搬 Google Fonts CSS2 API 现在返回的 `@font-face`（同样的 family、weight、style、`unicode-range`、`font-display: swap`），只把 `src` 改成站内文件。只保留 **latin** 与 **latin-ext** 两个子集。 | 去掉跨域渲染阻塞；不改设计 |
| D2 | 字体文件由执行者从 Google Fonts CSS2 API（用现代 Chrome UA 请求，拿到 woff2）下载后提交进仓库；同目录附上两款字体的 SIL OFL 1.1 许可文本（来源 `github.com/google/fonts` 的 `ofl/fraunces/OFL.txt`、`ofl/manrope/OFL.txt`）。**禁止**新增 npm 依赖（包括 `@fontsource/*`）。 | 零依赖；OFL 允许自托管，许可随字体分发 |
| D3 | 预加载最多 2 个字体文件：Fraunces 与 Manrope 的 **latin** 子集。`<link rel="preload" as="font" type="font/woff2" crossorigin>` 的 `href` 必须与构建后 CSS 中 `@font-face` 的 `src` URL **完全一致**（否则会重复下载）。 | 首屏文字所需；避免孤儿预加载 |
| D4 | 从 `index.html` 删除 Google Fonts 的 stylesheet 与两个 preconnect；全站构建产物不得再出现 `fonts.googleapis.com` / `fonts.gstatic.com`。 | 根因 1 |
| D5 | 只把三个依赖 `gi.json` 的页面（GL 计算器、GI 查询、GL 速查页）改为动态 `import()` 拆出入口包；其余 6 个页面保持静态 import。 | 入口包不再携带 279 KB 数据；改动面最小 |
| D6 | **首次加载不许闪屏**：`src/index.jsx` 在调用 `ReactDOM.render` 之前，若当前路径是三个拆分页之一，先 `await` 该页面模块，再用已解析的组件渲染。首次渲染**不得**经过 Suspense fallback（React 17 legacy render 会先提交 fallback，把预渲染 DOM 冲掉，造成白屏、CLS 和 LCP 回退）。`data-render-complete` 标记语义不变（仍在 render 回调里设置）。 | 保住预渲染的首屏 |
| D7 | 站内跳转（react-router 客户端导航）到三个拆分页时用 `React.lazy` + `Suspense`；fallback 必须渲染 `<SiteNav />` 加一行简短的加载提示，不得出现空白页。**不做**空闲时预取（避免在轻页面上产生计入 TBT 的长任务）。 | 导航体验与性能兼顾 |
| D8 | `vite.config.js` 加 `json: { stringify: true }`，让 JSON 模块以 `JSON.parse("...")` 形式产出。代码里对 JSON 的引用都是 default import，保持不变。 | 大 JSON 解析更快 |
| D10 | （2026-09-27 PF-02 执行中追加）Cloudflare Web Analytics 的 beacon `<script type="module">` 加 `async`，token、src 等其余属性不变。 | 非 async 的 module 脚本按文档顺序执行，排在入口之前的第三方 beacon 会让应用入口等它下载完才运行 |
| D11 | （同上追加）拆分出的 chunk 文件名不得包含（忽略大小写）`glcalc`：`GlCalculatorPage` 的 chunk 改名为 `gl-calculator-[hash].js`；verify-dist 断言 dist 中所有文件名及 HTML/JS 里引用的资源路径都不匹配 `/glcalc/i`。 | 守主 Spec「禁止 glcalc 变体」红线；资源网址对外可见 |
| D9 | 验收分两层：本地用构建产物做结构性断言（verify-dist + e2e）；线上 PSI 由编排者在部署后执行（PF-03）。本地 Lighthouse 波动大，**不作为**本 Spec 的通过条件。 | 本地测 46~65 与线上 70~71 的差距已证明本地不可靠 |

## §4 红线（违反即 ticket 失败）

1. 主 Spec §9 全部继承（禁迁框架、禁诊断分档、禁 glcalc 变体、MIT 署名不动等）。
2. `npm run check` 必须全绿；**不得删除或放松任何现有断言**。因拆包而需要调整的断言只能是等价或更严格的替换，必须在交付说明里逐条列出。
3. 不新增任何 npm 依赖；不引入新的第三方请求。
4. 9 个预渲染页面的静态内容（禁 JS 可见部分）、title/description/canonical/JSON-LD 零变化。
5. 视觉零变化：字体族、字重、字号不变；CSS 只允许新增 `@font-face`，不许改现有规则。
6. 不修改 `src/App.jsx` 的计算主流程，不修改 `formulas.js` / `display.js`。

## §5 Tickets

依赖序：PF-01 → PF-02 → PF-03（PF-01 与 PF-02 代码上相互独立，但按纪律串行执行；PF-03 需要两者都已部署）。

### PF-01 字体站内托管

**做什么**：按 D1~D4 把两款字体改为站内托管，删除 Google Fonts 引用，预加载两个 latin 子集文件。字体文件与 OFL 许可放在同一目录（位置由执行者决定：`src/assets/fonts/` 走 Vite 指纹，或 `public/fonts/` 用固定文件名，二选一，但必须满足 D3 的 URL 一致性）。

**Test plan**：

- verify-dist 新增断言：
  - ① `dist` 下所有 `.html` 与 `.css` 中不存在 `fonts.googleapis.com` / `fonts.gstatic.com`；
  - ② 构建后 CSS 含 Fraunces 与 Manrope 的 `@font-face`，且都带 `font-display: swap`；
  - ③ 每个 `@font-face` 的 `src` URL 在 `dist` 中都有对应文件；
  - ④ 9 个页面每页恰好有 1~2 个 `rel="preload" as="font"` 且带 `crossorigin`，每个 `href` 都出现在构建后 CSS 的 `@font-face src` 中。
- e2e（app 项目）新增：打开一个页面，监听网络请求，断言没有任何请求发往 `fonts.googleapis.com` / `fonts.gstatic.com`；`document.fonts.ready` 之后，`document.fonts.check('700 1em Fraunces')` 与 `document.fonts.check('500 1em Manrope')` 都为 true。
- 仓库中存在两份 OFL 许可文本，与字体文件同目录。
- `git diff package.json package-lock.json` 为空；`npm run check` 全绿。

### PF-02 拆分 gi.json 页面 + JSON.parse

**做什么**：按 D5~D8 改造 `src/index.jsx` 与 `vite.config.js`。三个拆分页的首次加载先 await 模块再 render；客户端导航用 lazy + Suspense（fallback 含 SiteNav）。交付说明里报告：构建后入口包大小、拆出的 chunk 列表与大小、预渲染 HTML 是否自动带上了 `modulepreload`（只报告，不强制）。

**Test plan**：

- verify-dist 新增断言：
  - ① 所有页面共同引用的入口 JS（`<script type="module" src="/assets/index-*.js">`）体积 **≤ 260 KB**（当前约 515 KB）；
  - ② 入口 JS 中 `carbs_per_100g` 出现次数 **≤ 5**（证明数据不在入口包里）；
  - ③ 存在一个包含 `gi.json` 数据的独立 chunk（出现次数 ≥ 4000）。
- e2e（app 项目）新增：
  - ① 从 `/gmi-calculator` 点击 SiteNav 的 Glycemic Load 链接，客户端导航后 GL 计算器的食物搜索输入框可见（断言页面没有整页刷新，例如导航前在 `window` 上设一个标记，导航后标记仍在）；
  - ② 同样方式导航到 `/glycemic-index-calculator` 和 `/glycemic-load-chart`，各自的 H1 可见；
  - ③ 首次直开 `/glycemic-load-calculator`：用 `addInitScript` 注册 MutationObserver，断言从 DOMContentLoaded 到 render 完成期间 `#root` 内的 `h1` 始终存在（不闪屏）。
